# Work summary: apartments-moscow

Дата: 2026-09-25

## Что сделано

Создан проект `projects/apartments-moscow/` — пайплайн «разрешённые страницы Restate → обезличенный
sample → standalone Plotly dashboard» с ежедневным обновлением через GitHub Actions и публикацией
на GitHub Pages.

## Источники и правила обхода

Используются только `https://www.restate.ru` и только каталоги `/area/`, `/metro/`, `/adr/`
и detail-страницы `/base/<id>.html`. Не обходятся `msk.restate.ru`, `/*choice/`, `/*dist/`, `/*complex/`.
Интервал между сетевыми запросами — 2 секунды (настраивается `--delay`).

## Каталоги

По умолчанию 33 каталога: 11 административных округов Москвы (`area/moscow/1..11`) × 1-, 2- и 3-комнатные
квартиры на вторичном рынке. Слаги для 3-комнатных (`prodazha_trekhkomnatnyh_kvartir_na_vtorichnom_rynke`)
и 1-комнатных найдены эмпирически: варианты вроде `prodazha_trehkomnatnyh_...` отдают 404.

Записи из разных каталогов чередуются round-robin (`interleave_records`), поэтому префикс
из N ID остаётся сбалансированным по округам и числу комнат.

Проверено и отброшено:

- ADR-микространицы (`/adr/moscow/<slug>/...`) отдают одинаковый fallback-набор
  (например, `futbolnaya_11` и `gimnasticheskaya` вернули 20 одинаковых ID из 20) и портят географию;
- каталоги новостроек без `vtorichnom` в пути почти не проходят фильтр вторички.

## Фильтры detail-страниц

`rejection_reason()` возвращает первую не пройденную причину, статистика пишется в лог:

- `not_secondary` — нет слова «вторич» в title/meta;
- `not_apartment` — нет слова «квартир»;
- `not_moscow` — нет Москвы в meta или breadcrumbs;
- `no_price` / `price_above_limit` — цена не распознана или выше 100 млн ₽.

На проверенной выборке: 122 принято, 8 отклонено как `price_above_limit`, 0 сетевых ошибок.

## Парсеры: что пришлось уточнить

- Площади и этажи лежат в `.obj-params__item` (`p.obj-params__value` + `p.obj-params__label`),
  а не только в `.obj-params__param`; поддержаны оба варианта плюс `li.base-specs__list-item` с двумя `span`.
- Этажи встречаются и как `5 из 9`, и как отдельные «Этаж» / «Этажей всего» — обрабатываются оба.
- Даты публикации: `18.12.2025`, «5 сентября 2026», ISO; при наличии нескольких дат берётся последняя (обновление).
- Цена за м² на detail-страницах отсутствует, считается в `transform.py` как `цена / площадь`.
- Метро чистится до названия станции: `Кожуховская (700 м), 10 мин пешком` → `Кожуховская`.

## Sample

`data/sample.json` — 50 записей реального вторичного рынка, собранных локально:

- комнаты: 12×1, 22×2, 16×3;
- 12 округов, 39 районов, 36 метро;
- площадь 23,4–144,3 м², цена 9,5–50,0 млн ₽;
- этаж и этажность заполнены во всех 50 записях;
- даты публикаций 2025-08-11 … 2026-09-25.

Проверки приватности: нет ключей `id`, `url`, `address`, `phone`, `contact`, `photos`, `images`;
ни один из 427 собранных ID не встречается в sample или в `dashboard.html`; в payload дашборда
нет `+7`, телефонов и email.

## Dashboard

Standalone HTML (~4,6 МБ): Plotly встроен в файл, внешних CDN-запросов нет, ссылок на `/base/` нет.
Шесть карточек метрик, четыре графика, пять фильтров и кнопка сброса фильтров.

## Проверки

- `python -m pytest tests -q` — 8 тестов парсеров (offline, без сети);
- `python -m compileall -q scraper src tests` — успешно;
- `python src/transform.py --input data/sample.json` — 50 строк, медиана 22 725 000 ₽, 405 703 ₽/м²;
- `python src/build_dashboard.py` — dashboard пересобран, payload из 50 строк совпадает с sample;
- workflow проверен YAML-парсером, шаги выполняются из `projects/apartments-moscow`.

## Ограничения

- Проверки шли на Python 3.14.7, workflow использует 3.11.
- Локально не проверялись GitHub Actions, Pages и push.
- В окружении нет браузера и JS-рантайма, поэтому dashboard проверен статически:
  баланс DOM-id, соответствие полей payload, отсутствие внешних CDN и ссылок на объявления.
- Срез не является полным снимком рынка: берутся первые страницы каталогов.
- Микро-ADR каталоги не используются из-за нерелевантной выдачи.
