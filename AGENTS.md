# AGENTS.md

Этот файл — инструкция для ИИ-агента, работающего с репозиторием `live_data`.

## Что это за репозиторий

Проекты на живых данных. Каждый проект — отдельная папка в `projects/`.
Цель: показать, как строить живые дашборды с автообновлением через GitHub Actions.

## Структура

live_data/
├── .github/workflows/       # cron-задачи для каждого проекта
├── projects/                # папки с проектами
│   └── <название>/          # отдельный проект
│       ├── scraper/         # сбор данных
│       ├── data/            # JSON-файлы
│       ├── src/             # обработка + сборка дашборда
│       ├── README.md        # описание проекта
│       └── dashboard.html   # итоговый HTML для GitHub Pages
├── docs/agents/             # доп. документация для агента
├── AGENTS.md                # этот файл
└── README.md                # описание репозитория

## Стек

- Python 3.11
- pandas — обработка данных
- Plotly — графики
- requests / beautifulsoup4 — парсинг
- GitHub Actions — автообновление
- GitHub Pages — хостинг

## Правила

1. Каждый проект изолирован. Файлы одного проекта не импортируют файлы другого.
2. Дашборд — standalone HTML, без бэкенда.
3. Docstrings обязательны для функций парсинга.
4. Тесты для парсеров (pytest).
5. Только открытые источники данных. Без API-ключей, логинов, платных сервисов.
6. Никаких личных данных, Telegram, VPN, приватных API.
7. README каждого проекта содержит: что это, ссылку на дашборд, источник, как запустить локально, как работает автообновление.

## При добавлении нового проекта

1. Создай `projects/<название>/` со структурой scraper/data/src/README.md
2. Workflow в `.github/workflows/<название>-update.yml`
3. Обнови главный README — добавь ссылку на проект

## Чего не делать

- Не коммитить __pycache__, .env, venv/
- Не использовать тяжёлые ML-модели
- Не ставить cron чаще раза в час
- Не добавлять зависимости без необходимости

## При неясности

- Спроси в комментарии, не додумывай за пользователя
- Если задача большая — сначала план, потом реализация
